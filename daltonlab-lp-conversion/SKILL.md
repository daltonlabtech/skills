# Dalton Lab: Landing Page de Alta Conversão

> Conversão é engenharia de contexto: quem chega, com qual dor, em qual estágio, e qual prova precisa.
> Clareza > criatividade. Resultado > feature. Velocidade > polimento.

---

## Passo 1 — Diagnose Antes de Construir

Antes de escrever uma linha de copy ou código, depure duas variáveis invisíveis:

### Variável 1: O Quem (ICP Psicográfico)

ICP demográfico (idade, renda, localização) é proxy ruim. O que importa é **contexto, dor e timing**.

| ❌ Demográfico (proxy ruim) | ✅ Psicográfico (critério real) |
|---------------------------|-------------------------------|
| "Donos de oficina, 40-50 anos" | "Ex-mecânico excelente tecnicamente, inseguro gerencialmente" |
| "Empresas de 1-10 funcionários" | "Founder que faz tudo sozinho e sente que está perdendo vendas por falta de resposta rápida" |

**ICP de verdade = critério de compra:** gatilho, dor, tentativa anterior e prova necessária.
Persona é biografia. Spec do usuário errada → o produto (a LP) falha.

### Variável 2: O Quando (Nível de Consciência — Eugene Schwartz)

Regra: **headline fala com o estágio atual. Prova empurra 1 estágio à frente.**

| Nível | Estado do Lead | Ângulo da Headline | Tipo de Prova |
|-------|---------------|-------------------|---------------|
| **01 Desconhecido** | Não sabe que tem o problema | Sintoma e identidade — *"Você ainda faz X desse jeito?"* | Diagnóstico simples, checklist, benchmark |
| **02 Problema conhecido** | Sabe que tem o problema, não sabe a solução | Custo e urgência — *"Se você tem X, está perdendo Y"* | Números, antes/depois, cálculo |
| **03 Solução conhecida** | Sabe que existe solução, não sabe qual | Trade-offs e seleção — *"3 formas de resolver X, por que a 3ª escala melhor"* | Comparação honesta, matriz |
| **04 Produto conhecido** | Conhece o produto, ainda não comprou | Diferenciação e proof stack — *"Por que nós, por que agora"* | Cases, demonstração, objeções |
| **05 Mais consciente** | Pronto para comprar, trava na fricção final | Risco e fricção — *"Troque X por Y em Z dias, sem risco"* | Garantias, onboarding, redução de esforço |

**Erro clássico:** tentar vender "Solução" para quem está no nível "Desconhecido" — é pedir em casamento no primeiro encontro.

## Passo 2 — Ordem de Debug (LP que não converte)

**Nunca comece pelo design.** Siga essa ordem:

```
1. ICP errado → redefine o avatar
2. Consciência errada → ajusta headline e ângulo
3. Prova insuficiente para o estágio → troca o tipo de prova
4. Só depois: design visual, cor do botão, layout
```

Não existe "taxa de conversão no vácuo". Existe conversão contextualizada. Tráfego certo + consciência errada = LP que não converte mesmo com design perfeito.

## Passo 3 — Checklist Tático (execução)

### Hero (acima da dobra)
- [ ] 1 promessa clara — o que muda para eles
- [ ] 1 público específico — para quem é
- [ ] 1 CTA com ação exata (sem "Saiba mais" — use "Começar agora", "Ver planos", "Quero testar")
- [ ] Visual do produto — mostra, não explica
- [ ] Selo de confiança acima da dobra

### Estratégia de Copy
- [ ] Headline com menos de 10 palavras
- [ ] Benefício primeiro, feature depois
- [ ] Linguagem do cliente, sem jargão técnico
- [ ] 1 transformação central, vários pontos de prova
- [ ] Dá para escanear em 5 segundos

### Prova Social
- [ ] Logos se você tem nomes reconhecíveis
- [ ] Métricas se você tem tração (números reais)
- [ ] Depoimentos específicos com resultado mensurável
- [ ] Zero elogio genérico ("Ótimo serviço!" não converte)

### Estrutura da Página
- [ ] Sequência: **Hero → Dor → Solução → Prova → CTA**
- [ ] No máximo 3 seções de features
- [ ] FAQ mata as 5 principais objeções
- [ ] CTA repetido 2 a 3 vezes ao longo da página

### Técnico
- [ ] Carrega em menos de 3s
- [ ] Mobile-first de verdade (não "também funciona no mobile")
- [ ] Nada de localStorage/sessionStorage no fluxo de conversão
- [ ] Fluxo de uma rolagem só — sem navegação lateral

## Erros Comuns

| Erro | Correção |
|------|----------|
| Mudar cor do botão antes de debugar ICP | Seguir ordem de debug — ICP → Consciência → Prova → Design |
| Headline genérica ("A melhor solução para sua empresa") | Headline com sintoma ou custo específico do ICP |
| Depoimento sem resultado ("Adorei o produto!") | Depoimento com número ("Reduzi 3h por dia de trabalho manual") |
| CTA genérico ("Saiba mais") | CTA com ação + benefício ("Testar grátis por 7 dias") |
| Mostrar features antes dos benefícios | Benefício primeiro, feature como prova do benefício |
| Página que funciona no desktop, "ok" no mobile | Mobile-first: desenha no celular, expande pro desktop |
